9.1 Performance

Lingotran's load is not uniform. It arrives in spikes shaped like a school timetable: thirty learners in one room start the same lesson within ninety seconds, four times a day.

Always load-test from a single source IP

Every learner in a school shares one NAT address. A load test that spreads across many IPs will never reproduce the failure that actually takes a school offline.

Minors

A large share of Lingotran learners are children. Any defect exposing learner identity, audio, or progress across account boundaries is a safeguarding incident with regulatory weight — not a normal severity-2 bug. Escalate immediately and never batch it into a sprint.

9.3 Accessibility — WCAG 2.1 AA

Public-sector and education buyers procure against accessibility conformance. For Lingotran this is a sales gate, not a nicety.

CheckHowLingotran-specific risk
Keyboard onlyUnplug the mouse; complete a full lessonRecord button is often a div with a click handler — unreachable
Focus visibleTab through every controlCustom-styled controls lose the ring
Screen readerNVDA / VoiceOver through one exerciseScore updates are silent — aria-live missing
Contrastaxe scan + manual on brand purpleCoral on white fails; use the text-safe variants
Non-audio pathComplete a lesson without hearing itA speech product must still serve deaf and hard-of-hearing learners
TimingRecording countdownsFixed limits disadvantage learners with motor or speech differences; must be adjustable
ErrorsTrigger every validation messageColour-only error states are invisible to colour-blind users
Zoom 200%Browser zoomLesson player clips or scrolls horizontally
Automation covers about a third

An axe scan in CI catches contrast, missing labels, and landmarks. It cannot tell you the tab order is illogical or the screen-reader announcement is meaningless. Budget manual passes for the lesson player every release.

10.2 Root cause analysis · LT-INC-0219

Summary. Monday 08:47, roughly 3,400 learners across eleven schools received 429 on sign-in. Duration 26 minutes. Resolved by raising the limit and restarting both instances.

WhyAnswer
1Users saw 429 — the login rate limiter rejected them.
2The limit is 10/min per IP, and every school presents one NAT address for all its learners.
3Per-IP is the middleware default; it was accepted unchanged when the limiter was added in LT-0904.
4The change was two lines and reviewed for correctness — nobody asked how it behaves against real customer network topology.
5The PR checklist covers correctness and coverage. It has no prompt about deployment topology or customer network shape.
Root cause

A process gap, not a coding error: security-relevant middleware is not evaluated against real customer traffic patterns.

ImmediateKey the limiter on IP + email rather than IP aloneBackend · same day

10.4 Production support

MinuteAction
0–5Confirm scope: one learner, one school, or all? Check error rate and 429 rate in Application Insights.
5–10Get a correlation ID from any affected request. It joins frontend, API, database, and speech in one trace.
10–20Establish what changed: last deploy, last migration, last flag flip, last config edit. Almost always one of these four.

The rule

Mitigate first, diagnose second. A rolled-back deploy costs a sprint's pride. A 40-minute investigation while eleven schools cannot teach costs a renewal.

11.1 Where the recurring prompts live

Anything explained twice belongs in a skill. These exist as files in .claude/skills/ and travel with the repo, so every engineer gets the same standard (13.2).

When you are…SkillWhat it enforces that a typed prompt forgets

Why not keep the prompts here

A prompt in a document is copied, edited and drifts. A skill in the repo is reviewed like code and applies identically for everyone. The worked examples below stay because they teach the shape of a framework, which a skill cannot.

11.2 Choosing a prompt framework

Each framework makes one field mandatory. That field is what stops the task's failure mode. Choose by what goes wrong, not by what the task is called.

FrameworkLoad-bearing fieldUse at Lingotran forDo not use for
TREF
Task · Restriction · Explanation · Format		Restriction — what must not be touchedAnything near learner data, production, or the database: SQL generation, log handling, blob accessOpen-ended design; the restrictions crowd out the thinking
TRACE
Task · Request · Action · Context · Evaluation		Evaluation — the model must run something and judge itselfATDD. Given/When/Then → Playwright spec → run → iterate (8.1). The QA-owned loopAnything with no runnable check; Evaluation degrades into a wish
CIDAM
Context · Intent · Details · Actions · Method		Method — the order of operationsMulti-file suite refactors: fixture restructuring, moving seeding from UI to API across many specsSingle-file edits; the ceremony costs more than the change
CO-STAR
Context · Objective · Style · Tone · Audience · Response		AudienceTwo things — house style on generated specs, and the readiness report written for a head of department (12.2)Work where correctness matters more than register
RISE
Role · Input · Steps · Expectation		Steps — the scaffold shapeGenerating a new k6 scenario, a fixture, or a corpus runner from an existing patternWork where the steps are the thing you are trying to discover
TAG
Task · Action · Goal		Speed. Nothing else.Reproducing a defect locally, a one-off terminal command, a throwaway queryAnything touching data or shipping. No restriction field, no evaluation field
TAG is the one that bites

The fastest to type, and the only one with no guard rail. No Restriction to keep a command off production. No Evaluation to make the model check itself. Fine for a local repro, dangerous everywhere else. The failure mode of AI in QA is not an answer that looks wrong. It is a plausible one nobody verifies.

Distrust list

AI will confidently invent Azure limits, PostgreSQL syntax, Playwright APIs that do not exist, WCAG criterion numbers and library behaviour. It will also write test cases that look thorough while missing the concurrency case that matters. Verify anything you would put your name on. Never paste learner data, audio, credentials or connection strings into a prompt.
