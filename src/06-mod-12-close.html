Wording matters

QA never signs "it is fine". QA signs "these are the risks, this is what is untested, this is what I recommend." The business owns the decision; QA owns the honesty of the information it is made on.

12.4 PR review checklist for QA

AskLooking for
Which trace layers change?Test that layer and everything downstream (2.2)
Any new route?Auth middleware present on it and on every sibling verb
Any new query?EXPLAIN on staging volumes; index present
Any migration?Reversible; concurrent index; expand/contract for renames
Any in-process state?Behaviour at 2+ instances (2.4)
Any check-then-act?Concurrency test required (5.3)
Any new flag?Both states plus the transition
Any external call?Timeout, retry, and what happens on failure
Any user-visible text?Escaped; translated; readable by a screen reader
Do tests assert behaviour?Not mock call counts (8.1)
Anything touching learner audio?Region, retention, deletion, sub-processors (7.4)

Test case counts, bugs raised per tester, or automation percentage. Each one is trivially gamed and rewards volume over judgement.

12.7 Glossary

TermMeaning here
QA / QC / QEAssurance = preventing defects through process; Control = finding them by testing; Engineering = building the systems that do both.
VerificationDid we build it to spec?
ValidationDid we build a thing a teacher can actually use in a classroom?
Shift leftQA in refinement, not after merge. Module 3 is shift-left in practice.
Shift rightLearning from production — smoke, alerts, escape analysis.
Test pyramidMany fast unit tests, fewer API tests, fewest E2E. Inverted pyramids are slow and flaky.
EscapeA defect that reached production. The gate that missed it is the finding, not the defect.
FlakeA test that fails without a code change. Treated as a defect in the suite.
REF corpusThe fixed reference clips in 7.3 — Lingotran's only scoring-quality regression signal.
Expand/contractTwo-release pattern for renames so old and new code run together safely.
