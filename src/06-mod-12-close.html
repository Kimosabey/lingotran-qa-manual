13.3 A skill, in full

.claude/skills/lt-pr-trace/SKILL.md
---
name: lt-pr-trace
description: Map a Lingotran PR diff onto the layer trace and list the tests
  each touched layer requires. Use when reviewing any pull request.
---

Read the diff. Do not summarise it back.

1. For every file changed, name the layer it sits at, using the eleven rows of
   the layer trace (LessonPlayer.tsx ... JSON envelope ... React render).
2. Output the layers touched, plus every layer downstream of them. A change
   at layer 9 can break all ten above it; a change at layer 7 cannot break layer 1.
3. For each layer in that set, list the concrete tests this diff requires.
4. Flag explicitly, as separate lines:
   - a new route whose sibling verbs were not also checked for auth
   - any new query with no EXPLAIN against UAT volumes
   - any check-then-act sequence (read, decide, write) — needs a concurrency test
   - any state held in process memory — behaves differently at 2 instances
5. End with what you could not determine from the diff alone.

Never state that a change is safe. Report what it touches and what that requires.

.claude/agents/flake-hunter.md
---
name: flake-hunter
description: Re-run a single Playwright spec repeatedly and classify whether
  it is flaky, genuinely failing, or order-dependent.
tools: Bash, Read, Grep
model: sonnet
---

Given a spec path:

1. Run it 30 times in isolation. Record pass and fail counts.
2. Run it 10 times with --shuffle alongside the rest of the suite.
3. Classify:
   - fails 30/30 isolated        -> a real defect, not flake
   - passes isolated, fails shuffled -> order dependence, usually a shared fixture
   - intermittent in both        -> genuine flake; capture the trace for each failure
4. Quote the actual failing assertion. Never paraphrase it.
5. Recommend: fix, quarantine, or delete — with the reason.

Do not modify the spec. Diagnose only.

13.7 The QA workstation

Three tools, one standard. The standard lives in the repo — AGENTS.md, CLAUDE.md and .claude/ — never in a tool's own settings, or three tools grow three versions of the house rules and the one your teammate uses is the one you never reviewed.

ToolUse it forDo not use it forConfig it reads
Claude CodeRepo-wide work, running build and verify, fan-out PR review, anything that must be gated—CLAUDE.md, .claude/
CursorWriting and refactoring one spec file, in-editor speedMulti-file agentic runs that need a gate.cursor/rules/*.mdc → points at the above
AntigravityDriving a real browser, capturing evidence, exploratory supportAnything trusted without a human reading itPoint it at AGENTS.md
Only one of them can gate

Claude Code is the only one carrying a deterministic hook — .claude/hooks/guard-db.py blocks a write, a production host or an inline credential whether or not the model cooperates. Cursor and Antigravity cannot be reached by it, so they honour the same rules by convention only. That is a real difference: their output re-enters through the pipeline like anyone else's, and gating stays with the deterministic layer.

A job that did not run is worse than one that failed

A failure is loud. A job that silently did not run looks exactly like a clean night. The report states every check including the zeros, and says plainly when something is missing — "cross-school rows: 0" and "cross-school check: DID NOT RUN" must never be confusable.

The governing rule

Agents propose; deterministic checks dispose. Every gate in this manual — the pipeline in 8.4, the REF bands in 7.3, the cross-school query in 6.2 — is a fact that either holds or does not, and none of them may be delegated to a model. Use Claude Code to widen what you look at and to make the standard identical between engineers. Never let it decide severity, readiness, or whether a score is correct (Module 11). The moment an agent can turn a gate green, the gate has stopped being one.

Before pasting anything

Never put learner audio, learner names, credentials, connection strings, or a production log excerpt into a prompt. Learners are minors and the audio is personal data under the school agreement (7.4). Redact to IDs and correlation IDs — they are enough to reconstruct a timeline and carry nothing about a child.
